# Hermes ↔ Synap MCP Architecture

Hermes (the headless Eve orchestrator) connects to Synap via the **Model Context Protocol (MCP)** — a typed function-call interface to Synap's 27 tools. This architecture allows Hermes to reason about and mutate Synap entities without maintaining its own state.

---

## Architecture Overview

```
Hermes (Python AI container)
    ↓
MCP Client (configured in ~/.eve/hermes/config.yaml)
    ↓
POST {pod}/mcp (JSON-RPC 2.0)
    ↓
Hub Protocol Router (packages/api/src/routers/mcp)
    ↓
checkPermissionOrPropose() → 27 Synap tools
```

**Key principle:** All Hermes ↔ Synap communication is **stateless**. Hermes reads from Synap, makes decisions, and writes results back. No local state, no agent cache.

---

## Tool Surface

Hermes has access to all 27 Synap MCP tools, organized into 8 categories:

- **Session & Discovery** — `synap_orient`, `synap_governance`
- **Entities** — `synap_search`, `synap_search_entities`, `synap_get_entities`, `synap_get_entity`, `synap_create_entity`, `synap_update_entity`
- **Relations & Graph** — `synap_get_relations`, `synap_link_entities`
- **Memory** — `synap_remember_fact`, `synap_recall_facts`
- **Knowledge** — `synap_get_knowledge`, `synap_list_knowledge`, `synap_write_knowledge`
- **Documents** — `synap_create_document`, `synap_get_document`
- **Channels & Messaging** — `synap_get_channel`, `synap_post_message`, `synap_send_message`
- **Proposals & Governance** — `synap_list_proposals`, `synap_revise_proposal`
- **Workspace & Structure** — `synap_list_profiles`, `synap_create_workspace`, `synap_create_view`
- **Capture** — `synap_capture`

All tools route through `POST {pod}/mcp` (Hub Protocol REST). Zero duplication or per-channel routing.

## DevPlane Trigger Loop

The **DevPlane trigger loop** is a **pg-boss cron worker** (`hermes-trigger-worker`) that dispatches work to Hermes every 60 seconds.

### Trigger Flow

1. **Watch Phase** — `hermes-trigger-worker` queries for `devplane_feature` entities with `agent_status = "idle"`
2. **Dispatch Phase** — For each idle feature, worker constructs context (entity, workspace metadata, recent messages) and fires a webhook to `HERMES_TRIGGER_URL` with `HERMES_TRIGGER_KEY` auth
3. **Hermes Processing** — Hermes receives the webhook, instantiates the appropriate sub-agent (using skill/engine dispatch), calls Synap MCP tools to gather context and write results
4. **Status Update** — Hermes calls `synap_update_entity` with `agent_status = "done"` (or `"error"` on failure)
5. **Polling Resumes** — Next cycle, worker skips the feature and picks up any new idle ones

### Environment Variables

Auto-injected by `eve install hermes` / `eve update hermes`:

| Variable | Purpose |
|---|---|
| `HERMES_TRIGGER_URL` | Webhook endpoint where worker sends dispatch payloads (e.g., `http://hermes:4000/trigger`) |
| `HERMES_TRIGGER_KEY` | Secret key for webhook auth (Bearer token) |

These live in the backend `.env` and are wired into the `hermes-trigger-worker` job queue configuration.

## Memory Plugin

Hermes includes a **Synap Memory Plugin** at `~/.eve/hermes/plugins/memory/synap/` that syncs conversation history to Synap knowledge facts.

### Behavior

- **On every turn** — Plugin extracts conversation context and calls `synap_write_knowledge` to create or update a knowledge document in the Synap workspace
- **Namespace** — `hermes_conversations`
- **Key pattern** — `{workspace_id}_{conversation_id}`
- **Content** — Markdown-formatted conversation transcript + reasoning

### Configuration

Plugin is auto-generated by `eve install hermes`. Location: `~/.eve/hermes/config.yaml`:

```yaml
mcp:
  clients:
    synap:
      url: "{pod}/mcp"
      headers:
        Authorization: "Bearer {api_key}"
```

Memory sync is **read-only from Hermes' perspective** — it always writes via `synap_write_knowledge`, letting Synap's governance layer decide approval.

## MCP Configuration

Hermes MCP client is configured at startup in `~/.eve/hermes/config.yaml`:

```yaml
mcp:
  clients:
    synap:
      url: "https://YOUR_POD.synap.live/mcp"
      headers:
        Authorization: "Bearer synap_user_..."
```

Pod URL and API key are auto-detected from `~/.eve/secrets.json` by the `eve install hermes` flow.

---

## What's NOT Here

- **Per-agentType routing** — Hermes uses the same 27 tools regardless of agentType. No specialized per-personality MCP endpoints.
- **WebSocket/streaming** — MCP is request-response only. For real-time updates, use event subscriptions on Synap channels.
- **Custom tools** — All tools come from Synap. Hermes cannot add its own MCP tools.
