## Overview

The Hermes daemon supports a **plugin system** based on a minimal `EvePoller` interface. A plugin is a custom poller that feeds work into the daemon's shared `TaskQueue` alongside the built-in pollers (TaskPoller, IntentPoller, FeaturePoller).

**DevPlane is the reference plugin.** It adds a feature pipeline poller that watches `devplane_feature` and `devplane_story` entity status changes and enqueues pipeline tasks (context-gather → plan → execute → verify → deploy) for the appropriate Hermes sub-agents.

The same pattern can be used to add any workspace-specific automation: CRM triggers, knowledge-base sync, scheduled code reviews, external webhook ingestion, etc.

---

## The `EvePoller` interface

```typescript
// packages/@eve/builder/src/lib/poller-interface.ts
export interface EvePoller {
  /** Called once per daemon poll cycle. Returns number of items queued. */
  pollOnce(): Promise<number>;
  /** Optional cleanup on daemon shutdown. */
  shutdown?(): Promise<void>;
}
```

That's the entire contract. `pollOnce()` is called on every daemon tick (default 30s). Return the number of tasks you enqueued — `0` is fine when there's nothing to do. `shutdown()` is called before the daemon exits; use it to flush or close connections.

## Registering a plugin

Call `daemon.registerPoller()` before `daemon.start()`:

```typescript
import { HermesDaemon } from '@eve/builder';
import { createDevPlanePlugin } from '@eve/builder/plugins/devplane';

const daemon = new HermesDaemon(config);

daemon.registerPoller(
  createDevPlanePlugin({
    apiBase: config.apiBase,
    apiKey: config.apiKey,
    queue: daemon.queue,
  })
);

await daemon.start();
```

Plugins registered this way are iterated after the three built-in pollers on every tick. Errors in a plugin's `pollOnce()` are caught and logged — they do not crash the daemon.

### Via `HermesConfig.plugins`

If you're using the `eve hermes` CLI command, you can declare which plugins are active via `~/.eve/secrets.json`:

```json
{
  "builder": {
    "plugins": ["devplane"]
  }
}
```

Plugin wiring from config is handled in `commands/hermes.ts`. Built-in plugins (like `devplane`) are resolved by name; future external plugins can be loaded by package path.

## Writing a new plugin

### 1. Create your poller

```typescript
// my-plugin/my-poller.ts
import type { EvePoller } from '@eve/builder/lib/poller-interface.js';
import type { TaskQueue } from '@eve/builder/lib/task-queue.js';

export class MyPoller implements EvePoller {
  constructor(
    private readonly apiBase: string,
    private readonly apiKey: string,
    private readonly queue: TaskQueue,
  ) {}

  async pollOnce(): Promise<number> {
    // 1. Query your data source (Synap entity, external API, etc.)
    const items = await this.fetchPendingItems();
    if (items.length === 0) return 0;

    // 2. Enqueue a Task for each item
    for (const item of items) {
      this.queue.enqueue({
        id: `my-plugin-${item.id}`,
        assigneeId: this.resolvePersonality(item),
        title: `[my-plugin] ${item.title}`,
        context: {
          // Arbitrary context — passed through to TaskExecutor
          pluginId: 'my-plugin',
          sourceId: item.id,
        },
        priority: 50,
      });
    }

    return items.length;
  }

  async shutdown(): Promise<void> {
    // Close connections, flush state, etc.
  }
}
```

### 2. Export a factory function

```typescript
// my-plugin/index.ts
import type { EvePoller } from '@eve/builder/lib/poller-interface.js';
import { MyPoller } from './my-poller.js';

export interface MyPluginConfig {
  apiBase: string;
  apiKey: string;
  queue: TaskQueue;
}

export function createMyPlugin(config: MyPluginConfig): EvePoller {
  return new MyPoller(config.apiBase, config.apiKey, config.queue);
}
```

### 3. Register at daemon startup

```typescript
import { createMyPlugin } from './my-plugin/index.js';

daemon.registerPoller(createMyPlugin({ apiBase, apiKey, queue: daemon.queue }));
```

## DevPlane plugin — reference implementation

**Source:** `packages/@eve/builder/src/lib/plugins/devplane/index.ts`  
**Wraps:** `lib/feature-poll.ts` (`FeaturePoller`)

```typescript
export function createDevPlanePlugin(config: DevPlanePluginConfig): EvePoller {
  const poller = new FeaturePoller({
    apiBase: config.apiBase,
    apiKey: config.apiKey,
    queue: config.queue,
    pollIntervalMs: config.pollIntervalMs,
  });

  return {
    pollOnce(): Promise<number> {
      return poller.pollOnce();
    },
  };
}
```

FeaturePoller watches `devplane_feature` and `devplane_story` entities. When a feature's `agent_status` transitions to a pipeline phase trigger (e.g. `todo` → enqueue context-gather task), it creates a Task assigned to the matching personality (context-gatherer, planner, executor, verifier, or deployer) and pushes it to the queue.

The five pipeline personalities are provisioned at workspace init by `useDevplaneSetup` in the DevPlane app. Hermes resolves them at startup via `personalityByAgentType` using their slug (`devplane_context_gatherer`, `devplane_planner`, etc.).

For the full pipeline state machine see the [DevPlane north star](../devplane/north-star.mdx) and the [DevPlane startup flow](../devplane/startup-flow.mdx).

## Architecture: where plugins sit

```
HermesDaemon._runLoop()  (every 30s)
  │
  ├─ TaskPoller.pollOnce()       built-in — polls entity.task for assigneeIds
  ├─ IntentPoller.pollOnce()     built-in — polls /api/hub/background-tasks
  ├─ FeaturePoller.pollOnce()    built-in — DevPlane feature pipeline (legacy path)
  │
  └─ for poller of extraPollers: — registered plugins
       poller.pollOnce()

TaskQueue  (shared FIFO, priority-ordered)
  │
  └─ _processQueue()
       → _resolvePersonalityForTask()
       → TaskExecutor.execute(task, personality)
       → post-execute: update entity status, record run
```

Built-in pollers and plugin pollers all share the same `TaskQueue`. Task dispatch (`_processQueue`) routes by `task.context` flags — plugins set these to control post-execute behavior (e.g., `isPipelineTask: true` triggers feature status update after the run).

## Conventions

| Convention | Detail |
|---|---|
| Task ID prefix | Use `<plugin-name>-<entity-id>` to avoid collisions with built-in task IDs |
| `task.context.pluginId` | Set to your plugin name — makes logs and post-execute routing unambiguous |
| Idempotency | `pollOnce()` will be called repeatedly. Don't enqueue the same task twice — check the queue or track in-flight IDs |
| Error handling | Throw from `pollOnce()` freely — the daemon catches and logs, then continues |
| Personalities | Plugins can assign tasks to any personality discovered by the daemon. Use `personalityByAgentType` slug if you define your own, or `personalityById` if you have the UUID |

## Adding a new built-in plugin

If a plugin is generic enough to ship with Eve (not workspace-specific), add it to:

```
packages/@eve/builder/src/lib/plugins/<name>/index.ts
```

Then wire it in `commands/hermes.ts` under the `config.plugins` switch. Keep the factory function signature consistent: `(config: XPluginConfig) => EvePoller`.
