Synap works in [Raycast](https://www.raycast.com) in two ways: Raycast AI talks to your pod's MCP server, and the
Synap extension adds its own commands (search, capture and review) to the launcher.

<Callout title="Not in the Raycast Store yet" type="warn">
  The Synap extension is not published in the Raycast Store, so you cannot install it yet. Raycast AI can use your pod
  today through its MCP server, as described below. Raycast AI needs Raycast Pro.
</Callout>

## Connect Raycast to your pod

With the CLI connected to your pod, run:

```bash
synap connect raycast
```

The CLI does two things:

- It creates a dedicated agent key for Raycast on your pod and stores it where the Synap extension reads it. By
  default the key covers the whole pod; `--workspace <id>` limits it to one space.
- It prints the fields to add your pod's MCP server to Raycast AI. In Raycast, run **Install MCP Server**, enter the
  name, the HTTP transport and the URL the CLI printed, and sign in with OAuth, then approve on your pod's consent
  page. If sign-in fails, the CLI also shows an `Authorization` header to use instead; the full key is in a file only
  you can read, and the CLI never prints it.

Raycast AI starts with a small set of essential Synap tools and loads more when a task needs them.

## Generate script commands

```bash
synap raycast generate
```

This command is hidden (it is not listed in `synap --help`). It writes a Raycast Script Command for each enabled
capability on your pod. Each script calls `synap capability run <verbId>` with the arguments the capability declares.

## If something does not work

- `synap doctor` checks that the key works and that the workspace exists on this pod.
- `synap pods use <name> --surface raycast` switches only Raycast to another saved pod.
