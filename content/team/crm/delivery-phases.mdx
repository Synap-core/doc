# Delivery Phases

The CRM is built incrementally. Each phase delivers a complete, usable slice of value — not a partial feature. Later phases build on earlier ones without breaking them.

---

## Phase 0 — Foundation ✅ Done

Workspace provisioning, authentication, shell navigation, and core tRPC wiring.

**What shipped:**
- Workspace auto-provisioning on first launch (`createFromDefinition`) with idempotent resume on failure
- `proposalId`-based deduplication — no duplicate workspaces created across sessions
- `AppTRPCProvider` with `workspaceLink` — `X-Workspace-Id` injected into all requests
- `AppStoresSync` — workspaceId synced from auth context to Zustand store
- CRM shell with sidebar navigation (Pipeline, Contacts, Companies, Activity, Find Leads)
- System profile stubs (event, task, note) in workspace definition for validator compatibility
- Vercel deployment pipeline with retry logic (`deploy.sh`)

## Phase 1 — Core Pipeline & Contact Management

**Goal**: A salesperson can work their full pipeline end-to-end — find leads, move them through stages, log activity, and view each contact's history.

**Deliverables:**

### Pipeline kanban
- Expanded card view (inline, no navigation away)
- Drag-and-drop between columns with optimistic status update
- Stuck deal detection with visual indicator
- Column filters (owner, ICP score, age in stage)

### Contact detail — Lead dashboard
- Replace 682-line custom detail page with entity panel system
- Register CRM panel sections: ICP data, activity timeline, next action, notes
- Status-aware layout: lead sections visible for `lead → call_booked` statuses
- Notes section using `DocumentEditorCell` — auto-creates document on first edit

### Company dashboard
- Contacts list by company
- Pipeline summary per company
- Revenue aggregation

### Home dashboard
- Wire BentoGrid to backend auto-save (`BentoAdapter`)
- Register and implement: `crm-pipeline-stats`, `crm-needs-attention`, `crm-recent-activity` widgets
- Remove unregistered `ai-inbox` widget reference (or stub it cleanly)

## Phase 2 — Client Lifecycle & Documents

**Goal**: Once a lead converts to a client, the team has everything needed to manage the relationship — contracts, shared documents, tasks, health tracking.

**Deliverables:**

### Client dashboard
- Status-aware panel layout switches when `crmStatus → client`
- Contracts section: lists document entities of type `contract` linked to this person
- Active tasks section
- Shared documents section (proposals, NDAs, meeting notes)
- Health indicator: computed from last activity date + open tasks

### Document template system
- Template entity type (`isTemplate: true`, `templateSchema` JSONB property)
- Template picker modal (lists available templates by type)
- Variable form: renders from `templateSchema`, auto-fills from entity properties
- `generateFromTemplate` tRPC mutation: renders content, creates document, links to entity
- Default template library seeded on workspace provisioning:
  - Service Agreement
  - Proposal
  - NDA
  - Meeting Notes
  - Onboarding Checklist
- "Save as template" action on any document

### Documents view
- Replace custom documents page with standard Synap `table` view scoped to document entities
- Filter by type (contract, proposal, NDA, note, other)
- Link to entity from document row

## Phase 3 — Discovery & Intelligence

**Goal**: The team can find and qualify new leads from within the CRM, with The Arch available as a manual source.

**Deliverables:**

### Find Leads page
- Replace mock UI with real lead discovery surface
- Manual lead creation form (name, email, company, source, ICP score)
- "Import from The Arch" action:
  - Server action reads `arch_lead` entities from The Arch workspace via Hub Protocol REST
  - Filters by fit band (configurable minimum — default: `promising_with_rework` and above)
  - Displays leads with band badge, capability scores, abstract
  - "Import" creates a `person` entity in the CRM workspace with `source: "The Arch"`, maps fields
  - Deduplication: checks for existing person with same email before creating

### ICP scoring
- ICP score input on contact detail (manual entry)
- Future: AI-assisted scoring via intelligence service

## Phase 4 — Automations & Pipeline Intelligence

**Goal**: Status changes trigger actions automatically; the pipeline surface itself surfaces more context.

**Deliverables:**

### Automation rules
Built on existing Synap automations system (pg-boss + automations router):

| Trigger | Action |
|---|---|
| Status → `contacted` | Create follow-up task (due +3 days) |
| Status → `call_booked` | Create task "Prepare call brief" |
| Status → `client` | Generate onboarding checklist from template |
| Status → `churned` | Create task "Send churn feedback request" |
| Stuck in stage >N days | Notify owner |
| `nextFollowUpDate` reached | Notify owner with contact context |

Automation rules are configured in CRM settings, stored as `automation` entities in the workspace.

### Pipeline full view
- Toggle between kanban and dense table view on the pipeline page
- Table sortable by estimated value, ICP score, age in stage
- Bulk actions: reassign owner, bulk status change

## Phase 5 — Client Channels & Connectors (Future)

**Goal**: Team collaboration per client, and external data surfaced in client dashboards.

**Deliverables:**

### Client channel
- Each `client` person/company gets an associated Synap thread channel on conversion
- Client dashboard surfaces this channel as a panel section
- Team members can discuss the client without leaving the CRM
- Channel persists; messages are searchable

### Standalone connectors
- Google Drive connector configurable directly on pod (no CP required)
- Google Calendar events auto-linked to contacts by email match
- Client dashboard "Google Drive" section becomes functional
- Nango self-hosted in Eve docker-compose stack
