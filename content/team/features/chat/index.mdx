# Chat

The AI chat experience lets users interact with Synap's intelligence layer through natural language. The OrchestratorAgent (co-founder persona) handles general queries across all tools, while PersonaAgents handle domain-specific tasks.

## Chat architecture

| Component | Description |
|-----------|-------------|
| **Multi-agent system** | OrchestratorAgent routes requests to specialist agents. Each has session-scoped memory with 4h personal / 30min others. Compaction engine manages memory overflow. [More details](/docs/architecture/concepts/multi-agent-system) |
| **Branching conversations** | Conversations can fork into branches. Branches are entity-scoped — useful for project-specific discussions. Supports parallel threads within a workspace. [More details](/docs/architecture/concepts/branching-conversations) |
| **Hub Protocol** | All chat messages flow through Hub Protocol REST (`/api/hub/chats`). Not tRPC — external agents also use this endpoint. Bearer token authentication. [More details](/team/platform/hub-protocol) |
| **Streaming** | Real-time streaming responses via Socket.IO + Yjs CRDTs. Agents stream tokens to frontends for typewriter-effect rendering. [More details](/team/studio/streaming) |

## AI actions in chat

When an AI agent needs to **mutate data** (create/update/delete entities), it goes through the proposal system:
1. Agent creates a `Proposal` with proposed mutations
2. If `DEFAULT_AUTO_APPROVE` applies, mutation is applied immediately
3. Otherwise, user reviews and approves in the Proposals tab
4. Proactive cells surface AI action opportunities for review

## Inline patterns and AI navigation

Since 2026-05-27, agents can embed typed patterns directly in their response text. The frontend renders them without a backend round-trip.

**Reference patterns** (always rendered, click-navigable):

| Pattern | Renders as |
|---------|-----------|
| `[[entity:UUID\|Name]]` | EntityLink chip |
| `[[view:UUID\|Name]]` | EntityLink chip |
| `[[doc:UUID\|Title]]` | EntityLink chip |
| `[[widget:CELL_KEY\|Label]]` | EntityLink chip |

**Command patterns** (permission-gated, rendered as action chips):

| Pattern | Action |
|---------|--------|
| `[[open:side\|view:UUID]]` | Open view in side panel |
| `[[open:main\|cell:CELL_KEY]]` | Open cell in main area |
| `[[run:UUID\|Label]]` | Trigger an automation |

These patterns are taught to all agents via the `ui-patterns.md` skill file, which loads for any agent with search or retrieval tools.

See [AI Inline Patterns](/team/platform/ai-inline-patterns) for the full syntax reference.

## Widget proposals in chat

When an agent generates a widget, a `WidgetPreviewChip` appears inline after the agent's message. The chip shows the widget title, type, and placement options. Clicking "Open in Side Panel" opens the `iframe-widget` cell, which self-fetches the widget definition and renders it.

Navigation permissions (`aiGovernance.navigationPermissions`) control whether action chips execute automatically or require user confirmation. Configured per-workspace in Settings → Intelligence → AI Navigation.

See [AI Companion Architecture](/team/platform/ai-companion) for the full package and component breakdown.
