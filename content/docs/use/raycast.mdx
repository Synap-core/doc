The Synap extension for [Raycast](https://www.raycast.com) gives you launcher commands to search your pod and capture
into it. Raycast AI reaches your pod through its MCP server, not through the extension.

## Connect Raycast to your pod

Install the Synap extension in Raycast. Then, with the CLI connected to your pod, run:

```bash
synap connect raycast
```

The CLI creates a dedicated agent key for Raycast on your pod and stores it where the extension's commands read it. By
default the key covers the whole pod; `--workspace <id>` limits it to one workspace.

## Connect Raycast AI (Raycast Pro)

The same command prints the steps. In Raycast:

1. Run **Install MCP Server**.
2. Enter a name, set the transport to **HTTP**, and use your pod's MCP URL, which the command prints.
3. Set authentication to **OAuth**, choose **Dynamic**, press **Sign In**, and approve on your pod's consent page.
   If sign-in fails, turn OAuth off and add the header `Authorization: Bearer <key>` instead. The command saves
   the full value in a private file and prints its path.
4. Press **Install MCP Server**. In Raycast AI, mention the server and ask anything.

A new connection starts with the nine essential tools and loads more when a task needs them. The extension no longer
adds AI tools of its own, so there is nothing to keep in step between Raycast and your pod.

## Generate script commands

```bash
synap raycast generate
```

This command is hidden (it is not listed in `synap --help`). It writes a Raycast Script Command for each enabled
capability on your pod. Each script calls `synap capability run <verbId>` with the arguments the capability declares.

## If something does not work

- `synap doctor` checks that the key works and that the workspace exists on this pod.
- `synap pods use <name> --surface raycast` switches only Raycast to another saved pod.
