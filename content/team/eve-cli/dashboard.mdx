## Overview

The Eve dashboard is a **visionOS-style personal OS** — not a traditional web admin panel. It runs locally as a Next.js app on **port 7979** (`hestia-cli/packages/eve-dashboard`). Every screen shares the same three-layer shell: an animated wallpaper, a frosted-glass popup pane, and a persistent dock. Apps render *inside* the pane; the wallpaper and dock never reload during navigation.

The dashboard reads the same `~/.eve/secrets.json` the CLI does, and drives component lifecycle through `@eve/lifecycle` — no privileged daemon required.

## Shell architecture

See the canonical design spec: [Eve OS Shell](../platform/eve-os-shell.mdx).

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   [animated mesh-gradient wallpaper — fixed, full-screen]   │  ← Layer 1
│                                                              │
│      ┌──────────────────────────────────────────┐            │
│      │                                          │            │
│      │           Popup app pane                 │            │  ← Layer 2
│      │   (rounded, frosted, scrollable inside)  │            │
│      │                                          │            │
│      └──────────────────────────────────────────┘            │
│                                                              │
│              ┌─────────────────────────┐                     │
│              │  Home  Agents  Settings │                     │  ← Layer 3
│              └─────────────────────────┘                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| Layer        | Role                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| **Wallpaper** | CSS mesh-gradient blobs drifting over a near-black base. GPU-only (`transform`/`opacity`). Respects `prefers-reduced-motion`. |
| **App pane** | `border-radius: 24px`, `backdrop-filter: blur(40px)`. Content cross-fades on navigation (140ms). The pane never re-animates on app switch. |
| **Dock**     | Centered pill at the bottom — the only navigation surface. Core apps (Home, Agents, Settings) are always pinned. User-pinned marketplace apps follow. |

## The four apps

### Home — app launcher

Design spec: [Eve OS Home — Design Spec](../platform/eve-os-home-design.mdx)

The first screen the operator sees on every launch. Four vertical zones inside the pane:

1. **Greeting** — time-of-day salutation with the operator's first name from CP, rendered in a soft gradient.
2. **Stat cards** — three translucent cards: Agents running, Events today, Updates available. Live data; click to navigate.
3. **App grid** — vivid colorful icons (UmbrelOS style) for every installed app and marketplace entitlement. `Cmd+K` focuses the capsule search that filters the grid live.
4. **Search** — sticky-ish capsule at the bottom of the pane body.

The `+ Add` icon at the end of the grid opens the Marketplace (Phase 2: external `synap.com/marketplace`; Phase 4: in-OS `/marketplace` pane).

### Agents — agentic triangle

Design spec: [Eve Agents — Design Spec](../platform/eve-agents-design.mdx)

The operator's window into the live agentic stack. Two toggleable views sharing the same event stream:

| View         | What it shows                                                                               |
| ------------ | ------------------------------------------------------------------------------------------- |
| **Flow**     | ReactFlow graph of the agentic triangle (OpenClaw → Synap → Hermes). Edges pulse with real traffic. Node panels open on click for per-agent status and config. |
| **Timeline** | Chronological list of channel events — message received, task dispatched, result returned. Each row expands to its full payload. |

The **Connect Channels** modal (top-right of the pane header) manages external messaging integrations: Telegram bot token, Discord bot token, WhatsApp via Baileys.

### Settings — tabbed admin

Settings renders inside the same OS pane as a tab strip. All legacy admin pages are preserved as internal tabs:

| Tab              | What it does                                                                            |
| ---------------- | --------------------------------------------------------------------------------------- |
| Components       | Full component catalog — install / start / stop / restart / update / remove, streaming logs, per-component config panels (RSSHub feeds, OpenClaw MCP/voice/messaging, Hermes daemon, Synap backups) |
| AI Providers     | Per-provider CRUD with API keys + default models. "Apply to components" propagates keys to every consumer. |
| Networking       | Domain & SSL form, subdomain map with live DNS check, read-only Traefik config preview. |
| Doctor           | Mirrors `eve doctor` — probe results for platform / network / containers / AI / wiring, with inline Repair buttons. |
| Channels         | Channel-config toggles (legacy surface, recontextualized as a Settings tab).            |
| Stack Pulse      | Organ chips and component status table — the former `/dashboard` content.               |

### Marketplace

Browse and install apps from the Synap marketplace catalog. Phase 2: opens `synap.com/marketplace` in a new tab. Phase 4: renders as a full in-OS pane at `/marketplace`. See the [Eve OS Roadmap](../platform/eve-os-roadmap.mdx) §3.2 for the migration plan.

## Auth model

Eve OS uses **Synap CP OAuth** (PKCE). The flow:

1. `eve ui` on the host opens `http://localhost:7979`.
2. First visit: "Sign in to Synap CP" → PKCE handshake with `cp.synap.sh/oauth/authorize`.
3. CP redirects back to `localhost:7979/auth/callback`.
4. First-time user: `/setup/pair-pod` — pick an existing pod from CP entitlements or create a new one.
5. CP issues a per-pod API key → Eve writes it to `~/.eve/secrets.json` → OS Home loads.

Returning visitors skip steps 2–4 (token cached). There is no local hex key to type.

```
│   │   ├── networking/      ← Domain + Traefik
│   │   ├── doctor/          ← Diagnostics
│   │   ├── channels/        ← Channel-config toggles
│   │   └── stack-pulse/     ← Former /dashboard
│   └── marketplace/
│       └── page.tsx         ← Marketplace (/marketplace) — Phase 4
├── auth/callback/page.tsx   ← outside the shell
├── login/page.tsx           ← outside the shell
└── setup/pair-pod/page.tsx  ← first-launch pod pairing
```
